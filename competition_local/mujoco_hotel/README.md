# 酒店与B2W/Piper的MuJoCo适配

使用迁移的默认比赛酒店`Collected_task03/hotel/task03.usd`，其中包含实际B2W轮足机器狗与背载Piper；不使用替代机器人，也不安装Isaac Sim。原始资产只读，所有转换结果放在本目录。

原版小脑与操作已通过行走、低/高位模式、夹爪、回零、末端IK和入口楼梯实测。模型保留24个驱动和12个源相机，材质665个、纹理223项（含背景）。395个原USD层逐文件SHA256与迁移收据一致。旧静态预览的300秒站立测试与当前原小脑测试分开记录。

入口：在项目目录运行`competition_local\view_hotel.ps1`。窗口初始为酒店总览，鼠标点击顶部Follow/Overview/Head/Hand选择视角，Reset重新开始。所有原机器人键位不用于视角控制。

头相机与夹爪相机已对照原酒店USD和原采集程序重新校准。两台安装位置/朝向与原版一致；头相机焦距4.8858mm、水平视场130°，夹爪6.0492mm、水平视场120°，水平孔径均20.955mm。原IsaacLab采集使用640×480、fx=fy，垂直孔径按这个比例计算；窗口默认最大化，Head/Hand视图按4:3投影等比例放大铺满窗口，裁去超出窗口的边缘，不拉伸图像；顶部Fit 4:3可切换完整画幅，再按Fill恢复铺满。显示裁切不改变640×480传感器标定或采集参数。操作提示默认收起，Help/Hide help用鼠标展开/收起，不占原键位。原USD的相机坐标包含嵌套变换，转换时比较实际刚体局部坐标，不能直接复制某一层的平移数值。

已修复MuJoCo近裁剪按全场景extent缩放的问题：旧`.01`实际为0.508m，会裁掉近处夹爪，现在实际近裁剪为原版0.01m。`camera_audit.json`逐项核对源参数、转换后位姿和实际投影；640×480分割渲染验证夹爪张开/闭合分别有31387/15225个夹指像素，旧参数均为0。校准后画面见`camera_after_head_open.png`和`camera_after_hand_open.png`。这是相机几何校准，MuJoCo光照/材质仍与Isaac RTX有差异。修改后未新增传感器或改动原资产/操作键位。

| 键 | 作用 |
|---|---|
| 1 / 2 | 原行走 / 楼梯小脑模式 |
| 4 / 5 | 低位抓取 / 高位抓取模式，完成后锁定腿与轮关节，基座保持自由 |
| W / S、A / D | 按住前进/后退、左/右转，松开归零。Walk前进0.65m/s、后退0.45m/s，转向0.60rad/s；楼梯模式0.25m/s |
| 空格 | 清空移动/IK按键状态并停止指令 |
| R/T、E/G、V/B、N/M、I/O、K/L | 机械臂关节1至6的负/正方向，每次0.035rad |
| C / P | 夹爪关闭到0.001m / 打开到0.045m |
| H | 机械臂1秒平滑回零 |
| 方向键、PageUp/PageDown | 原机械臂基坐标系XYZ末端平移，点按1cm，持续按住移动 |
| 7/8、9/0、-/= | 原末端三个转动方向，点按5度 |
| Q / Esc | 退出 |

与原版相同，机械臂、IK和夹爪须先进入4或5并等待锁腿完成。1会解除锁腿、立即恢复行走并同时让机械臂回零。3/J/Y/U/Z/X保留禁用；F1/F2/F3保留采集含义，当前未启用record_dir采集适配，不绑定其它功能。

按用户反馈已将Walk前进从0.25提高到0.65m/s。顶部Walk − / Walk +鼠标按钮每次调整0.1m/s，范围0.25至1.0m/s，不占原键位；速度显示在窗口中，保存到control_settings.json并支持热加载。楼梯速度单独设置。walk_speed_validation.json实测走廊前进4秒2.603m（0.651m/s），前后与转向保持直立，松键/空格停止通过。

交互窗口现使用迁移的三个原始小脑checkpoint进行CPU推理：行走57维、楼梯57维、高度稳定75维，恢复原驱动与动作尺度。MuJoCo连续轮角被转换为PhysX相同的[-2π,2π]传感器范围，低位高度观测转换为相对地面的训练坐标。物理轮角和自由基座不被传送或伪造。旧HotelSimulation的600/20静态预览控制只供旧独立测试，交互窗口OriginalTeleop已恢复源160/5腿部驱动。

`original_controls_validation.json`证明原键位、松键停止、夹爪、回零、1cm末端移动等实际通过；`stair_trial_wrapped.json`证明原楼梯小脑在原酒店入口这段楼梯连续25秒前进、机身升高0.572m且保持直立。其它楼梯/地形没有据此泛化认证。6个C4已恢复独立动态刚体，详见下方夹取测试；其余物件与门仍固定，整机在酒店的完整抓放任务尚未验收。

灰色建筑的原因是原USD仅引用外部MDL定义，缺失的默认贴图不在USD输入属性里。现已从NVIDIA官方同名材质库补回38个模块及其中的原色彩图，修复材质子集绑定与低面数几何逐面角UV。Plaster_Wall的R/G/B分别是AO/污渍/漫反射，按原MDL的B通道、颜色和亮度默认值烘焙，避免将通道数据误当紫色RGB。下载原URL、SHA256和仍未找到的模块见material_defaults.json。MDL程序化纹理、反射、玻璃与RTX照明仍有近似，不作像素级一致承诺。恢复效果见hotel_restored_textures.png。

`inspect_assets.py`复制USD层到独立短路径缓存并重写派生引用，解决Windows长路径；不保存原始层。`build_hotel.py`读取原网格、关节、质量、质心和惯量，生成MuJoCo资产。显示网格做LOD，MDL材质近似映射为漫反射颜色/纹理；同一网格的材质子集与UV接缝可能有差异。原酒店约2600万面，转换报告记录实际保留面数。

碰撞按USD的每个独立网格建立凸近似，机器人沿用原碰撞几何、关闭本体自碰撞。地板、独立墙体和楼梯可保留各自结构；凹形门框和家具细节尚需进一步分解。不能把当前碰撞预览等同于完整比赛物理验收。[MuJoCo碰撞说明](https://mujoco.readthedocs.io/en/stable/computation.html)、[USD物理模式](https://openusd.org/dev/api/usd_physics_page_front.html)。

`validate_hotel.py`检查模型编译、自由基座站立接触及有限状态，输出validation.json与预览图。实际结果以该文件为准。`conversion_report.json`记录源路径、源SHA256、网格LOD、关节和限制。`viewer_status.json`记录本轮窗口状态。



## 2026-10-25 C4动态物理恢复

- 原版/World/C4下6个C4均为非运动学动态刚体，子网格标注质量0.0099999998kg。初期转换只为机器人建立刚体，误把C4烘焙进静态world，导致夹不动。
- restore_c4_objects.py将6组原几何与材质重新挂到独立自由刚体，保持初始世界位姿，采用源质量；无显式源惯量时用原网格凸包计算。碰撞掩码允许机器人、桌面/场景与C4相互接触。未增加焊接、吸附或强制跟手。
- 修复HotelSimulation.reset对新增物体自由关节的处理；原机器人操作键位、夹爪驱动和相机参数保持。未来build_hotel.py重建也会应用此修复。
- c4_validation.json：6个C4均在酒店支撑面稳定接触；easy_C4_1受0.15N横向力0.16秒后移动0.112m。
- c4_grip_validation.json：使用真实转换夹指/C4和原夹爪驱动的独立接触台架，从上方夹取并规定夹爪抬升0.12m，C4靠接触/摩擦实际抬升0.1119m。该台架验证夹持接触，不能代替整机酒店导航/IK抓放验收。水平夹取初始台架会滑脱，因此仍须正确对准和夹住两侧。
- C4_1/easy_C4_1的源碰撞是SDF，当前MuJoCo沿用凸近似；其它物件与门维持原适配范围，不因本修复泛化为全部动态。

## 2026-10-25 夹持持续滑移修复（当前运行版本）

- 已复现水平夹持10秒约9.23mm滑移。单纯增大摩擦系数没有消除持续微滑，加倍夹爪增益在被测姿态反而更容易滑脱。本次保留kp=2000、阻尼25、原力上限500N与滑动摩擦系数1，启用MuJoCo NoSlip 3次后处理；物体仍完全依赖接触/摩擦，没有物体焊接、吸附或强制跟手。
- 当前派生XML及未来build_hotel.py均保留NoSlip3、原夹指碰撞体、6个源尺寸精确C4凸包和12组专用接触。CoACD拆分候选未显示额外夹持收益，没有应用到当前模型。不要重复启动分解任务。
- grasp_stability_validation.json：居中水平、向前端偏置15mm和从上方夹取，均通过30秒保持、平移、90°翻转及主动张开释放。保持漂移小于0.001mm，翻转相对变化小于0.32mm，张开后自由下落10–12cm。向掌部深入15mm的另一个初始姿态没有建立双侧接触，未混入成功夹持统计；任意夹持姿态不能据此保证。
- grasp_noslip_locomotion.json：原Walk四秒2.588m、入口楼梯25秒升高0.569m通过，键位不变。
- c4_validation.json已重新实测当前模型。旧验证器把平动/转动速度混为同一个阈值，并对2ms接触微振采样混叠；现改为逐物理步测量实际COM位移，并在失败时写失败状态，防止残留旧成功报告。6个C4的200ms最大COM摆幅0.035mm且无持续位移，真实外力推移通过。历史失败日志保留，不将旧报告冒充当前结果。
- 新窗口在抓取模式显示C4 GRIP L/R的左右法向接触力，viewer_status.json保留实际接触数、驱动力与NoSlip参数。一侧为0表示该侧没有测到C4接触，不能当作双侧夹实。所有原机器人按键及相机参数保持。
